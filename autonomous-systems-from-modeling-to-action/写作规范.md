# 写作规范（GitHub / GitBook 发布兼容规范）

本文档约定本书 markdown 内容的写作规则，保证在 GitHub（MathJax）、GitBook（KaTeX）等平台上正常渲染，并避免 docx → markdown 转换引入的错误。

## 1. 数学公式规范

### 1.1 上标星号：禁止裸 `^*`

`x^*` 中的 `*` 会被 markdown 强调解析吃掉，导致上标报错（"Missing open brace for superscript"）。

- 错误：`x^*,u^*`
- 正确：`x^{\ast},u^{\ast}` 或 `x^\*,u^\*`

### 1.2 宏命令白名单

GitBook 的 KaTeX 不允许 `\operatorname` 等宏。

- 错误：`\operatorname{rank}(A)`、`\operatorname{Re}(\lambda_i)`
- 正确：`\mathrm{rank}(A)`、`\mathrm{Re}(\lambda_i)`

其他禁用/避免的宏：`\newcommand`、`\def`、`\color`、`\href`。

### 1.3 公式内禁止 Unicode 数学符号

docx 导出的 Unicode 符号（∈、≤、×、→、ℝ 等）在部分渲染器中会丢失或错位。

- 错误：`x ∈ R^n`
- 正确：`x \in \mathbb{R}^n`

常用对照：∈→`\in`，≤→`\le`，≥→`\ge`，×→`\times`，→→`\to`，≠→`\ne`，∑→`\sum`，∫→`\int`。

### 1.4 矩阵与换行

- 用 `\begin{bmatrix}...\end{bmatrix}`，行间用 `\\` 分隔；不要手写 `[ ... ]` 拼矩阵（转换时反斜杠会丢失）
- 上下标尽量用花括号包裹：`x^{2}`、`q_{i}`（即使单个字符也建议包裹，避免转换工具误判）

### 1.5 公式块排版

- `$$` 前后各留一个空行
- `$$` 块内不要有空行（会被渲染器拆成两个独立块）
- 行内公式用单个 `$...$`

## 2. 结构规范

- 章节文件命名：`NN-中文标题.md`，放在所属篇目录下（`01-System/`、`02-Modeling/` …）
- 每章标题下保留「小节导航」列表，小节链接使用显式锚点
- **新增小节时**：先在 `SUMMARY.md` 中注册条目，再在章节正文的对应标题上方加显式锚点：
  ```html
  <a id="chN-secM"></a>
  ## N.M 小节标题
  ```
  显式锚点保证 SUMMARY.md 与正文的链接永久稳定（不随标题文字变化）
- 每章末尾保留「上一章 · 目录 · 下一章」导航
- 术语书写遵循 [CONTRIBUTING.md](./CONTRIBUTING.md) 的「中文术语（English Term, ABBR）」约定

## 3. Git 提交规范

- 提交信息使用英文，遵循 Conventional Commits：`docs: ...`、`fix: ...`
- 一个提交只做一类事情（修公式、加章节、改导航分开提交）
- 提交前自检清单：
  - `grep -nF '^*'`：不应有裸 `^*`（`^{\ast}` 和 `^\*` 除外）
  - `grep -nF '\operatorname'`：应为空
  - 数学行内无 Unicode 数学符号
  - 新小节已注册到 SUMMARY.md 且锚点存在
