## 33.1 连续理论怎样进入数字计算机

机器人本体、接触和电机主要由连续时间物理规律描述，而处理器只能在离散时刻读写有限精度的数。设连续系统为
```math
\dot x(t)=f\!\left(x(t),u(t),w(t)\right),\qquad
y(t)=h\!\left(x(t)\right)+v(t),
```
其中 $`x\in\mathbb R^n`$ 是状态， $`u\in\mathbb R^m`$ 是控制输入， $`y\in\mathbb R^p`$ 是测量， $`w`$ 、 $`v`$ 分别表示过程扰动和测量噪声。数字实现需要依次完成采样、状态估计、控制计算、通信和保持，最终形成
```math
x_{k+1}=f_d(x_k,u_k,w_k;T_k),\qquad
y_k=h_d(x_k)+v_k,
```
其中 $`t_k`$ 是第 $`k`$ 次采样时刻， $`T_k=t_{k+1}-t_k`$ 是实际采样间隔。离散模型不是另一套物理规律，而是连续系统在给定采样与保持机制下的时刻映射。

对线性时不变模型 $`\dot x=Ax+Bu`$ ，若区间 $`[t_k,t_{k+1})`$ 内输入保持不变，精确离散化为
```math
A_d=e^{AT},\qquad
B_d=\int_0^T e^{A\tau}B\,d\tau,\qquad
x_{k+1}=A_dx_k+B_du_k.
```
这里 $`A\in\mathbb R^{n\times n}`$ 、 $`B\in\mathbb R^{n\times m}`$ ，相应地 $`A_d\in\mathbb R^{n\times n}`$ 、 $`B_d\in\mathbb R^{n\times m}`$ 。工程中可用块矩阵指数同时计算 $`A_d`$ 和 $`B_d`$ ，避免在 $`A`$ 不可逆时套用 $`A^{-1}(A_d-I)B`$ 。非线性系统则通过数值积分、局部线性化或流映射近似获得 $`f_d`$ 。

仓储移动操作机器人可以在任务层使用连续轨迹，在底盘控制器中每隔数毫秒求一次速度或轮矩指令，在机械臂伺服器中以更高频率更新关节控制量，再由驱动器把数字命令变成电压和电流。连续控制器的稳定性结论只有在采样、延迟、量化和执行器边界均被纳入后才可迁移到真实系统；“把公式放进循环”本身并不保证闭环性质。

<a id="ch33-sec2"></a>
## 33.2 Sampling

采样是把连续信号 $`y(t)`$ 映射为序列 $`y_k=y(t_k)`$ 的过程。理想均匀采样满足 $`t_k=kT_s`$ ，采样频率为 $`f_s=1/T_s`$ ，角采样频率为 $`\omega_s=2\pi f_s`$ 。频率超过奈奎斯特频率 $`f_s/2`$ 的成分会折叠到低频：对正弦信号而言， $`f`$ 与 $`|f-\ell f_s|`$ 在采样点上可能不可区分，其中 $`\ell`$ 为整数。这种混叠是信息丢失，不能靠后端滤波完全恢复。

实际传感器并非理想冲激采样器。相机具有曝光窗口，IMU 和电流采样电路具有模拟带宽，编码器计数还可能在控制周期内累积。因此采样模型应包含前端滤波和时间窗口，例如
```math
y_k=\int g_k(\tau)y(t_k-\tau)\,d\tau+v_k,
```
其中 $`g_k`$ 是归一化采样核。若信号近似带限到 $`B`$ Hz，理论重构要求 $`f_s>2B`$ ；控制系统通常需要更高裕量，并在模数转换前配置抗混叠低通滤波器。冲击接触、轮胎打滑等信号并不严格带限，此时只能依据关注频带和允许误差设计采样链路。

仓储机器人可用 1 kHz 采集关节编码器和电流、以数百赫兹读取 IMU、以 20～60 Hz 接收相机帧。把最新相机位置直接标成控制循环当前时刻，会把曝光和传输延迟误认为运动，因此采样值必须附带采集时间戳。采样频率越高并非总是越好：它会增加噪声带宽、通信流量和处理负荷，也可能使差分速度估计被量化误差主导。

<a id="ch33-sec3"></a>
## 33.3 Zero-Order Hold

零阶保持（Zero-Order Hold，ZOH）表示数字控制器在相邻更新之间保持输出不变：
```math
u(t)=u_k,\qquad t\in[t_k,t_{k+1}).
```
它是多数数模转换器、总线命令接口和周期性伺服器的基础模型。ZOH 与采样共同定义离散被控对象；只离散化微分方程而不说明输入在周期内如何变化，所得 $`B_d`$ 没有完整物理含义。

ZOH 的连续频率响应可写为
```math
H_{\mathrm{zoh}}(j\omega)=\frac{1-e^{-j\omega T}}{j\omega T}
=e^{-j\omega T/2}\frac{\sin(\omega T/2)}{\omega T/2}.
```
它带来随频率增加的幅值衰减，并近似引入半个采样周期的相位延迟。若闭环带宽接近采样频率，保持器的相位影响不可忽略。前向欧拉近似 $`A_d\approx I+AT`$ 、 $`B_d\approx BT`$ 仅在 $`T`$ 相对系统最快时间常数足够小时可靠；精确 ZOH 离散化虽然消除了线性模型的积分误差，却不会消除模型误差或计算延迟。

机械臂驱动器可能每 $`1`$ ms 接收一次目标转矩，并在周期内保持该目标；但功率级往往以数十千赫兹 PWM 开关，内部电流环也会多次更新。因此“保持的是转矩目标”不等于“电机端电压恒定”。当驱动器使用线性插值、一次保持或内部轨迹生成器时，应按真实保持规律建模，不能机械地假定 ZOH。

<a id="ch33-sec4"></a>
## 33.4 Discrete Control Loop

离散控制循环通常按照“触发—采集—估计—控制—限幅—发送—保持”运行。以状态反馈为例，
```math
\hat x_{k|k}=\mathcal E(\hat x_{k|k-1},y_k),\qquad
u_k=\pi(\hat x_{k|k},r_k),
```
其中 $`\hat x_{k|k}\in\mathbb R^n`$ 是吸收当前测量后的状态估计， $`r_k`$ 是参考量， $`\pi`$ 可以是 PID、LQR、MPC 或非线性控制律。预测模型以 $`x_{k+1}`$ 为递推对象，是因为计算机在时刻 $`k`$ 持有当前信息，并要预测下一采样时刻的状态。

真实循环必须说明命令何时生效。若在 $`t_k`$ 采样后计算得到的 $`u_k`$ 只能于 $`t_{k+1}`$ 执行，则系统实际为
```math
x_{k+1}=A_dx_k+B_du_{k-1}.
```
可以引入增广状态 $`z_k=[x_k^\mathsf T,u_{k-1}^\mathsf T]^\mathsf T`$ ，把一周期延迟显式纳入设计。忽略该延迟会高估相位裕度，尤其影响高带宽电流环和机械臂关节阻抗控制。

仓储机器人中，底盘控制可先融合编码器与 IMU，再计算轮速；机械臂控制则需在同一状态快照上计算六个关节命令。若某些传感器来自上一周期、另一些来自当前周期，数学上的 $`y_k`$ 实际不是同时测量，应由估计器按时间戳传播。循环还必须处理无效数据、通信超时、数值异常和执行器饱和；这些离散逻辑是闭环的一部分，而不是控制公式之外的附属代码。

<a id="ch33-sec5"></a>
## 33.5 Numerical Integration

数值积分用于从 $`\dot x=f(x,u,t)`$ 近似计算离散流映射。显式欧拉法为
```math
x_{k+1}=x_k+T f(x_k,u_k,t_k),
```
局部截断误差为 $`O(T^2)`$ ，固定时间区间上的全局误差为 $`O(T)`$ 。经典四阶 Runge–Kutta 通过四次函数求值获得 $`O(T^4)`$ 的全局精度，但计算量和中间存储更大。隐式欧拉法
```math
x_{k+1}=x_k+T f(x_{k+1},u_k,t_{k+1})
```
需要求解代数方程，却对刚性电机电气模型或强阻尼接触模型更稳定。

积分方法的选择不能只比较阶数。以标量系统 $`\dot x=\lambda x`$ 为例，显式欧拉稳定要求 $`|1+T\lambda|<1`$ ；连续系统即使满足 $`\operatorname{Re}(\lambda)<0`$ ，过大的 $`T`$ 仍会使离散仿真发散。机械系统常采用半隐式欧拉：先更新速度，再用新速度更新位置，它通常比完全显式方法更好地保留能量结构。对姿态 $`R\in SO(3)`$ ，直接积分九个矩阵元素会破坏 $`R^\mathsf TR=I`$ ，应使用指数映射 $`R_{k+1}=R_k\exp(T[\omega_k]_\times)`$ 或积分后进行受控归一化。

在控制器内部，积分还出现在 PID 积分项、观测器和在线轨迹生成中。若周期变化，应使用实际 $`T_k`$ ，例如 $`I_{k+1}=I_k+T_ke_k`$ ，并结合抗饱和机制。高阶积分器不能补偿错误模型，也不能替代足够的采样频率；当接触切换、摩擦死区或限位碰撞导致动力学不光滑时，需要事件检测或混杂模型，而不能依赖光滑积分误差阶数。

<a id="ch33-sec6"></a>
## 33.6 Quantization

量化把连续幅值映射到有限集合。对量化步长 $`\Delta`$ 的均匀舍入量化器，
```math
Q(z)=\Delta\,\operatorname{round}(z/\Delta),\qquad
e_q=Q(z)-z.
```
在未饱和时有 $`|e_q|\le \Delta/2`$ 。若量化误差与信号近似独立且在区间内均匀分布，可用方差 $`\Delta^2/12`$ 的白噪声近似；这一假设对缓慢信号、周期轨迹和闭环极限环往往不成立。

编码器分辨率决定最小可辨位置。例如每转 $`N`$ 个计数时，角度步长为 $`\Delta_\theta=2\pi/N`$ 。用差分计算速度
```math
\hat\omega_k=\frac{Q(\theta_k)-Q(\theta_{k-1})}{T}
```
会使速度量化步长随 $`1/T`$ 增大，因此缩短周期可能反而使低速估计更跳跃。相机像素、ADC 位数、PWM 占空比分辨率和定点数格式同样引入量化。工程上可使用时间窗计数、模型观测器、误差反馈或适度抖动减弱确定性极限环，但这些方法都会引入延迟或噪声。

量化器还存在动态范围边界。若 ADC 输入、电流命令或整数累加器饱和，误差不再受 $`\Delta/2`$ 限制；定点溢出甚至可能改变符号。实现时应规定缩放、舍入、饱和和溢出语义，并在最坏状态下验证。对仓储机器人，厘米级导航量化可能可接受，而抓取时的毫米级位姿误差和低速关节爬行则可能不可接受，分辨率必须相对于任务误差预算选择。

<a id="ch33-sec7"></a>
## 33.7 Control Frequency

控制频率 $`f_c=1/T_c`$ 是控制律更新的速率，不必等于传感器采样频率、估计频率或执行器 PWM 频率。选择 $`f_c`$ 的目的，是在关键动态、延迟裕度、计算负荷和噪声之间取得平衡。若被控对象关注的最高闭环频率为 $`f_b`$ ，常把 $`f_c`$ 取为 $`f_b`$ 的若干倍至十余倍，但这只是起始经验，不是稳定性定理；最终应依据离散模型和相位裕度验证。

周期变短可减小保持误差，却也缩短可用计算时间，并扩大测量噪声与差分量化的影响。对于连续极点 $`\lambda_i`$ ，离散极点为 $`z_i=e^{\lambda_iT_c}`$ 。当 $`T_c`$ 减小时，稳定极点聚集在 $`z=1`$ 附近，对有限精度和模型辨识提出不同要求；当 $`T_c`$ 过大时，快速模态可能被混叠或失去足够的控制相位。

移动操作机器人可令电机电流环运行在 10～40 kHz，关节速度或转矩环运行在 1～2 kHz，底盘运动控制运行在 100～500 Hz，局部规划运行在 10～50 Hz。频率分层建立在时间尺度可分离、接口变量明确的假设上。若机械臂与底盘发生快速动态耦合，或末端接触刚性环境，低频上层不能继续把下层视为瞬时理想执行器。

<a id="ch33-sec8"></a>
## 33.8 Bandwidth

带宽描述系统能够有效跟踪或抑制的频率范围，它不是控制循环频率的同义词。在线性反馈系统中，环路传递函数为 $`L(s)=P(s)C(s)`$ ，灵敏度与互补灵敏度分别为
```math
S(s)=\frac{1}{1+L(s)},\qquad
T(s)=\frac{L(s)}{1+L(s)}.
```
低频处较小的 $`|S|`$ 有助于抑制扰动和模型偏差，而高频处较小的 $`|T|`$ 有助于抑制测量噪声。闭环带宽通常由 $`T`$ 的幅频特性定义，但不同定义可能给出不同数值，工程文档必须说明采用的指标。

采样、保持和延迟限制可实现带宽。纯延迟 $`\tau`$ 对频率 $`\omega`$ 增加相位 $`-\omega\tau`$ ，不会改变幅值，却可能耗尽相位裕度。若总延迟为 $`\tau_d`$ ，则交越频率 $`\omega_c`$ 处仅延迟造成的相位损失约为 $`\omega_c\tau_d`$ 弧度。因此控制频率远高于目标带宽仍不充分：相机处理的几十毫秒延迟、总线排队和驱动器内部滤波都可能成为主导因素。

机械臂自由空间运动可使用较高位置带宽，而接触货架或抓取纸箱时，过高带宽会放大结构柔性、齿隙和力传感噪声。底盘带宽还受轮胎附着与载荷转移限制。带宽设计默认线性化在工作点附近有效；大范围饱和、接触切换和强非线性情况下，应结合时域约束、鲁棒性分析和实验辨识，不能只依靠一个频率数字判断性能。

<a id="ch33-sec9"></a>
## 33.9 Real-Time Requirement

实时系统的正确性同时取决于计算结果和结果产生的时间。任务 $`\tau_i`$ 可用周期 $`T_i`$ 、最坏执行时间 $`C_i`$ 、相对截止时间 $`D_i`$ 和释放时刻序列描述。实时并不等于平均速度快：平均耗时 $`0.2`$ ms 的任务若偶尔阻塞 $`20`$ ms，可能比稳定耗时 $`0.8`$ ms 的任务更危险。

硬实时任务要求所有规定条件下都满足截止时间，失约可能导致失稳或安全风险；坚定实时任务允许极少失约，但过期结果应丢弃；软实时任务的延迟主要降低体验或性能。电机过流保护、换相和安全制动通常接近硬实时，底盘速度闭环属于硬实时或坚定实时，而仓库地图可视化多为软实时。分类应由失约后果和安全分析决定，而不是由所用操作系统名称决定。

实时保证依赖明确边界：处理器频率、缓存行为、中断负载、通信重试、温度降频和共享资源阻塞都需纳入假设。动态内存分配、无界循环、不可控日志写入和页面换入会破坏执行时间上界。对于复杂感知算法，通常不强求完整硬实时证明，而是用隔离、超时、降级和安全监控，使其延迟不会直接破坏底层稳定闭环。

<a id="ch33-sec10"></a>
## 33.10 Deadline

截止时间是任务结果必须可用的最晚时刻。若任务在 $`r_{i,k}`$ 释放，绝对截止时间为
```math
d_{i,k}=r_{i,k}+D_i,
```
完成时刻为 $`f_{i,k}`$ ，则响应时间 $`R_{i,k}=f_{i,k}-r_{i,k}`$ ，满足截止时间要求 $`R_{i,k}\le D_i`$ 。周期与截止时间可以不同：1 ms 周期的电流环可能要求命令在采样后 200 μs 内写入 PWM，而不是只要求在下一周期前完成。

端到端截止时间还应覆盖任务链。一次 IMU 测量经过采集、总线传输、状态估计、控制计算和命令下发后才产生物理作用。若每个阶段仅保证自己的局部周期，却没有统一释放关系，数据可能等待整个下游周期，形成显著年龄。因而应为链路分配子截止时间，并规定超期策略，如保留上一安全命令、进入受限速度模式或触发受控停车。

截止时间不等同于执行时间。高优先级抢占、锁竞争、DMA 总线占用和网络排队都会使响应时间大于代码运行时间。设计时应使用最坏情况或有可信置信边界的执行时间，而不能用平均性能报告代替保证。对于环境和硬件无法给出严格上界的系统，应诚实采用概率性时序指标，并通过独立安全层限制失约后果。

<a id="ch33-sec11"></a>
## 33.11 Latency

延迟是事件发生到相应结果产生之间的时间差。控制链总延迟可分解为
```math
\tau_{\mathrm{tot}}
=\tau_{\mathrm{sense}}+\tau_{\mathrm{queue}}+\tau_{\mathrm{compute}}
+\tau_{\mathrm{comm}}+\tau_{\mathrm{act}},
```
分别对应传感、排队、计算、通信和执行器响应。测量延迟决定控制器看到的是多旧的状态，命令延迟决定控制作用何时生效；二者在状态估计和闭环建模中不应混为一谈。

固定延迟可以用离散增广状态、预测器或带时间戳的回溯更新处理。例如延迟 $`d`$ 个周期的输入满足
```math
x_{k+1}=A_dx_k+B_du_{k-d}.
```
非整数周期延迟则可通过连续模型分段积分或分数延迟近似表示。补偿依赖模型准确性和延迟可测性；在轮胎打滑、货物碰撞等不可预测扰动下，长延迟造成的信息缺失不能被模型完全弥补。

相机从曝光中点到目标位姿输出可能延迟数十毫秒，而 IMU 仅延迟数百微秒。仓储机器人高速转弯时，若直接融合两者的“最新值”，视觉位置和惯性姿态对应不同物理时刻。正确做法是按测量时间更新历史状态，再传播到控制当前时刻。降低延迟通常比单纯提高处理吞吐量更有利，但批处理、滤波窗口和网络聚包会在吞吐与延迟之间形成权衡。

<a id="ch33-sec12"></a>
## 33.12 Jitter

抖动是周期、释放时刻、完成时刻或通信延迟围绕名义值的变化。若
```math
T_k=T_0+\delta T_k,\qquad |\delta T_k|\le J_T,
```
则 $`J_T`$ 可作为周期抖动上界。平均周期正确并不能消除抖动影响，因为控制器、积分器和滤波器面对的是每一个实际 $`T_k`$ 。抖动还可能具有相关性，例如垃圾回收、网络拥塞或热降频造成持续多个周期的长尾。

周期抖动使离散系统成为时变系统：
```math
x_{k+1}=A_d(T_k)x_k+B_d(T_k)u_k.
```
若控制器仍使用固定 $`T_0`$ ，会产生模型误差；可在时间戳可靠且计算允许时按 $`T_k`$ 更新积分、预测和滤波系数。另一种方法是把 $`\delta T_k`$ 作为有界不确定性进行鲁棒分析。前者不能消除命令到达时间的不确定性，后者又可能因上界过于保守而降低性能。

对六轴机械臂，关节命令若不同步到达，抖动还会改变笛卡尔轨迹和末端姿态。对无人机，IMU 循环中的百微秒级抖动可能明显影响高带宽姿态环；对慢速仓储底盘，同样数值可能可以忽略。可接受抖动必须相对于闭环带宽、相位裕度和安全距离确定，而不能用统一的毫秒阈值判断。

<a id="ch33-sec13"></a>
## 33.13 Multi-Rate System

多速率系统让不同任务按照各自动力学和计算需求运行。设基础时钟为 $`T_0`$ ，任务 $`i`$ 的周期为 $`T_i=M_iT_0`$ ，其中 $`M_i`$ 为正整数，则任务之间可在超周期
```math
T_H=\operatorname{lcm}(M_1,\ldots,M_q)T_0
```
上形成重复调度。整数倍关系便于确定性实现，但真实相机、网络和异步传感器未必与基础时钟整齐对齐。

快环向慢环汇总数据时，可采用抽取前低通滤波，防止高频成分混叠；慢环向快环提供参考时，可使用保持、插值或轨迹生成器。若慢层在时刻 $`k`$ 产生目标 $`r_k`$ ，快层不应默认该目标连续可微。对位置目标进行突变式 ZOH 会诱发速度和加速度尖峰，因此机械臂驱动器通常生成满足速度、加速度或冲击度约束的中间轨迹。

仓储移动操作机器人可采用 20 kHz 电流环、1 kHz 关节伺服、200 Hz 底盘与状态估计、30 Hz 视觉、10 Hz 局部规划和 1 Hz 任务调度。该分层默认内层闭环相对于外层足够快且稳定，外层可用简化后的闭环模型。若抓取过程中底盘与机械臂协同运动，则二者的状态需要在共同时间基准上交换；不能仅依靠“各自频率够高”推断整体协同正确。

<a id="ch33-sec14"></a>
## 33.14 MCU、CPU 与 FPGA

MCU 集成处理核心、定时器、ADC、PWM 和通信外设，具有较可预测的中断响应与低功耗，适合电机电流环、编码器采集和安全状态机。通用 CPU 具有更强浮点、缓存、虚拟内存和操作系统生态，适合优化、估计、视觉和规划，但执行时间受缓存未命中、调度和内存系统影响更大。FPGA 通过空间并行硬件实现固定数据通路，可获得微秒甚至更低的确定延迟，适合编码器接口、高速 PWM、时间戳和多轴同步。

硬件选择可抽象为吞吐量、单次延迟、确定性、数值精度、功耗和开发成本之间的权衡。若算法每周期需要 $`N_{\mathrm{op}}`$ 次操作，处理器峰值算力并不能直接给出执行时间，因为访存、分支和外设等待同样占用预算。FPGA 也不是自动“更实时”：跨时钟域、定点缩放和主机接口若设计不当，仍会引入不确定行为。

典型移动操作机器人可由 CPU 运行定位、MPC 和视觉，MCU 负责底盘与六轴机械臂的伺服接口，驱动器内部 MCU 或 FPGA 完成电流采样和 PWM。安全急停不应依赖高层 CPU 的正常调度。异构架构的边界在于接口复杂度：跨处理器传输会增加延迟、时间同步和故障模式，因此只有当隔离收益或计算需求超过通信代价时才值得拆分。

<a id="ch33-sec15"></a>
## 33.15 Interrupt 与 Scheduler

中断使硬件事件能够抢占当前程序，例如定时器到期、ADC 转换完成或 CAN 帧到达。中断服务程序应完成最小、确定且有界的工作：记录时间戳、搬运数据、清除标志并唤醒任务。若在高优先级中断中执行矩阵优化、阻塞通信或日志输出，低优先级任务会遭受难以分析的延迟。

在固定优先级抢占调度下，任务 $`i`$ 的最坏响应时间可迭代估计为
```math
R_i=C_i+B_i+\sum_{j\in hp(i)}
\left\lceil\frac{R_i}{T_j}\right\rceil C_j,
```
其中 $`C_i`$ 是最坏执行时间， $`B_i`$ 是低优先级任务持锁造成的最大阻塞， $`hp(i)`$ 表示优先级高于 $`i`$ 的任务集合。若迭代结果满足 $`R_i\le D_i`$ ，则在相应独立性和执行时间上界假设下，该任务可调度。共享总线、不可屏蔽中断和多核干扰需要另外计入。

优先级反转发生在高优先级任务等待低优先级任务持有的资源时，可使用优先级继承或优先级上限协议限制阻塞。双缓冲和无锁单生产者单消费者队列可降低控制任务等待，但仍需定义数据一致性。仓储机器人应让电流保护、伺服更新高于地图构建和日志任务；不过最高优先级任务若持续超载，整个系统仍会饥饿，因此还要配置运行时间监控和故障降级。

<a id="ch33-sec16"></a>
## 33.16 时间戳与同步

时间戳回答“数据对应何时”，同步回答“不同设备的时钟是否表示同一时间”。设备 $`i`$ 的本地时钟可近似写为
```math
c_i(t)=\alpha_i t+\beta_i+\eta_i(t),
```
其中 $`\alpha_i`$ 是频率偏差， $`\beta_i`$ 是时钟偏置， $`\eta_i`$ 表示噪声和短期漂移。只校正一次偏置而不估计频率偏差，设备运行一段时间后仍会逐渐失步。

时间戳应尽量在事件发生附近由硬件生成。软件在收到相机帧或 CAN 帧后才打戳，会把排队与调度延迟混入采样时间。同步方法包括共享触发线、分布式时钟、双向报文估计和外部统一时源。双向同步通常假设上下行延迟近似对称；网络拥塞破坏该假设时，偏置估计会产生系统误差。

对移动操作机器人，IMU 角速度、轮编码器、机械臂关节位置和相机曝光应投影到共同时间轴，再由估计器传播到查询时刻。空间外参准确而时间偏置错误，同样会产生随速度增大的定位误差：若机器人速度为 $`v`$ 、时间偏差为 $`\Delta t`$ ，一阶位置误差约为 $`\|v\||\Delta t|`$ 。同步精度应由允许状态误差反推，而不是盲目追求某个协议的标称精度。

<a id="ch33-sec17"></a>
## 33.17 SPI、UART、CAN 与 CAN FD

SPI 是同步主从总线，通常包含时钟、数据和片选线，协议开销低、速率高，适合板级连接 ADC、编码器和 IMU；但其物理距离短，片选数量和布线随设备增加。UART 是异步点对点串行接口，使用起始位和停止位恢复字符边界，实现简单，适合调试、低速传感器和配置接口，但原生不提供多节点仲裁与强实时保证。

CAN 使用多主广播和按标识符逐位仲裁，高优先级帧可在竞争中无损胜出，并提供错误检测与故障隔离。若帧 $`i`$ 的传输时间为 $`C_i^{\mathrm{bus}}`$ ，其响应时间不仅包含自身传输，还包括低优先级帧的不可抢占阻塞和高优先级帧干扰。总线利用率接近上限时，低优先级帧延迟会迅速增加。CAN FD 扩大数据段并允许数据阶段使用更高比特率，但仲裁阶段及网络拓扑仍限制总体时序。

在仓储机器人中，SPI 可连接驱动板上的电流 ADC，UART 可用于维护控制台，CAN 或 CAN FD 可连接轮毂驱动器、机械臂关节和电池管理系统。设计时必须给出报文周期、长度、优先级、超时与总线负载，而不能只声明“采用 CAN”。电磁环境、终端电阻、线束长度和接地会影响误码；错误重传提升可靠性，却会增加最坏延迟，因此安全命令还需配合本地超时和失联策略。

<a id="ch33-sec18"></a>
## 33.18 EtherCAT 与网络控制

EtherCAT 让以太网帧经过各从站时被在线读写，减少逐节点存储转发开销，并通过分布式时钟支持多轴同步。主站按周期发送过程数据，各驱动器在约定时刻锁存输入并更新输出。其价值不仅是高带宽，更在于可规划的周期通信和统一时基，适合六轴机械臂与移动底盘的协同伺服。

网络控制系统可表示为带延迟和丢包的离散系统：
```math
x_{k+1}=A_dx_k+B_du_{k-d_k},\qquad
\gamma_k\in\{0,1\},
```
其中 $`d_k`$ 是时变网络延迟， $`\gamma_k=0`$ 表示本周期命令或测量不可用。接收端可在丢包时保持上一命令、使用预测值或进入安全状态。不同策略对应不同闭环模型；只有在延迟和连续丢包长度有界、模型误差可接受时，预测补偿才可能保持既定性能。

EtherCAT 的确定性依赖专用拓扑、主站调度、从站实现和网络负载，不应与普通办公以太网的平均吞吐量混淆。若视觉流量、日志和伺服报文共享非实时网络，交换机排队会形成长尾延迟。工程上通常隔离实时过程网络与大带宽感知网络，并在驱动器本地保留电流环、限位和安全停止；上位网络失效时，不应让执行器无限期保持危险命令。

<a id="ch33-sec19"></a>
## 33.19 从算法周期到系统时序预算

算法给出的“1 kHz 控制”只是系统需求的起点。完整周期应分解为采样窗口、数据传输、任务释放、估计、控制、输出通信和驱动器锁存。若命令必须在周期 $`T`$ 内生效，可写出预算约束
```math
C_{\mathrm{sense}}+C_{\mathrm{in}}+W_{\mathrm{sched}}
+C_{\mathrm{est}}+C_{\mathrm{ctrl}}+C_{\mathrm{out}}
+C_{\mathrm{act}}+M\le T,
```
其中各 $`C`$ 表示相应阶段的最坏耗时， $`W_{\mathrm{sched}}`$ 是调度等待， $`M`$ 是为抖动、测量误差和未来功能保留的裕量。各项必须基于相同边界条件，不能把平均通信时间与最坏计算时间相加后称为最坏预算。

以周期 $`T=1`$ ms 的机械臂关节伺服为例，可以分配：传感锁存与输入传输 120 μs，状态估计 100 μs，控制计算 180 μs，限幅与安全检查 50 μs，输出传输 120 μs，驱动器锁存 80 μs，调度和共享资源阻塞上界 100 μs，并保留 250 μs 裕量。这里的数值只是结构示例；真实预算应通过静态分析、硬件跟踪和压力测试获得，并覆盖缓存冷启动、总线竞争、错误帧和温度降频等条件。

时序预算还要检查数据年龄与多速率链路。设测量采集时刻为 $`t_s`$ 、命令生效时刻为 $`t_a`$ ，则控制决策面对的端到端年龄为 $`A=t_a-t_s`$ 。即使每个任务都在局部截止时间内完成，错误的相位安排也可能让 $`A`$ 接近两个或更多周期。可通过采样触发、任务偏移和总线时隙协同安排，减少不必要等待。相机等异步数据则应在估计器中按时间戳处理，而不是强行等待以对齐所有输入。

最终验收应同时覆盖功能、数值和时间：记录实际 $`T_k`$ 、响应时间、端到端延迟、丢包、超期次数和命令生效时刻；在最坏载荷下验证稳定性与安全降级；检查超时后执行器是否进入定义状态。若实测上界超过模型假设，应降低带宽、重新分配任务或调整硬件，而不能仅放宽监控阈值。数字实时执行的目标不是让每段代码“尽量快”，而是让信息和控制作用在可证明或可验证的时间边界内到达。

## 本章小结

本章把连续状态空间、估计与控制律连接到数字硬件上的实际闭环。连续动力学只有在采样、保持和离散流映射被明确后，才能成为 $`x_{k+1}=f_d(x_k,u_k;T_k)`$ ；数值积分、量化和有限精度决定计算结果与理论模型之间的误差；控制频率与闭环带宽相关但不等价，采样延迟、保持器和执行器动态共同限制可实现性能。

进一步地，实时正确性要求周期、截止时间、延迟和抖动均有清楚定义。多速率架构通过时间尺度分离组织相机、IMU、底盘、机械臂和电机任务，但必须依靠时间戳、同步、调度分析及有界通信来维持一致状态。MCU、CPU、FPGA 以及 SPI、UART、CAN、CAN FD 和 EtherCAT 各自提供不同的吞吐、确定性和故障边界，硬件名称本身不能代替端到端时序分析。

最终，算法周期必须落实为覆盖采集、估计、控制、通信与生效时刻的系统预算，并为超期、丢包、饱和和失联定义安全行为。下一章将沿着这一执行链继续向物理端推进：研究电机与执行器如何把离散的电压、电流、转矩或位置命令转化为真实作用，以及内层电流环、功率电子器件和机械传动如何限定上层控制器可用的执行接口。
